# Vendored SWI3S Visualizer placement tests

These fixtures port the standalone **SWI3S Visualizer**'s test suite
(`mipi-soundwire-I3S-visualizer/test/`) into SWI3S Studio so the placement the
Studio shares with the Visualizer (the verified C++ cascade) is regression-tested
here, with no dependency on the sibling repo.

- The configs are the repository's `visualizer_examples/`, copied from the Visualizer, with the
  intentional-error configs moved and the quotes inside the Description field of six
  spec_figures CSVs doubled so each file is well-formed CSV (PDM_Streams_With_Sample_Grouping,
  _DLV_PHY, _FBCSE_PHY2, PDM_Streams_with_PHY_Tail_Bits, Single_Mic_PHY1_FBCSE,
  Single_Mic_Using_SRI_for_Reduced_Control_Bandwidth_PHY1_FBCSE); a re-sync from the
  Visualizer must reapply the doubled quotes. `directed_tests/test_mode_zeros.csv` carries
  PortMode_REG 2 (Test0) and `directed_tests/test_mode_ones.csv` carries 3 (Test1), the spec's
  DPn_PortMode values (`tests/test_port_mode_encoding.py` pins both); a re-sync must reapply
  them:
  - `directed_tests/` (65) — targeted feature/edge-case configs. The 18 that report a bus
    clash, a placement error or a warning on purpose are in `directed_tests/intentional_errors/`
    here, where the Visualizer keeps them with the rest; its `README.md` lists them.
  - `spec_figures/` (30) — configs reproducing MIPI SoundWire I3S spec figures
  - `use_cases/` (1) — a real-world example
- `golden/` and `golden_json/` follow the same layout.
- `golden/` — the Visualizer's **raw per-data-port placement** for each config,
  generated from its `test/model_dump.py` (which drives the Visualizer's own
  `DataPort` model). One `dp row col SLOT` line per owned slot; a `# rows N`
  header records the row count (the config's `RowsToDraw`).

`tests/test_visualizer_placement.py` solo-places every enabled data port through
`swi3score.grid_from_csv` and asserts the `(dp, row, col, slot)` set matches the
golden for all 90 configs that have one. Column 0 (CDS) is excluded — Studio reserves it for the
control stream.

- `golden_json/` holds the Visualizer's serialized bus model for each config (the files in
  its `test/test_json_outputs/`, same `<category>/<name>.json` layout). It is read by
  `tests/test_visualizer_engine.py`, which compares the swviz engine's model with it.

`authoring_render_golden.json` in this directory is not part of that vendored set: it is
Studio's own characterization of the authoring render, regenerated by
`tests/test_authoring_render_golden.py --regenerate`, so a re-sync from the Visualizer leaves it
alone.

To regenerate a `golden/` file after an intentional placement change, run the Visualizer's
`python3 test/model_dump.py <config.csv> <RowsToDraw>` for the config. Each output line is
`dp row col SLOT ch bit`; keep the first four fields of each line and write
`# rows <RowsToDraw>` as the first line of `golden/<category>/<name>.txt`. Regenerate
`golden_json/` with the Visualizer's own test suite, which writes `test/test_json_outputs/`.
