# SWI3S Studio v3.0.19

Analysis mode shows several SWI3S Links side by side; Open Capture is one page that says what
a file is before decoding it; each mode's menus show only what applies to it, with a new
Decode menu; and the waveform colours and line weights can be set. It also carries the work
of 3.0.18, which was never released: the command line is back (`-o` writes the bus model
without opening a window), the large-capture memory guard reads free memory on every
platform, the demos carry a skipping 44.1 kHz port, and three ways a check could pass without
looking are closed.

Per-release detail is the changelog block at the top of `swi3s_studio/__init__.py`, newest
first; this file is the summary of the 3.0.19 entry. Gated on every supported platform before
tagging.

## Multiple Links

- A SWI3S Link (spec §4.7) is one Manager and its Peripherals on one bus. Analysis mode now
  holds several, from separate capture files (**File ▸ Open Capture…**, *Add to them*) or
  from further clock/data pairs of the same file, which Open Capture offers when a file has
  spare channels. Links may differ in PHY, column count and row rate.
- The Links share one time base. Links from one file are aligned from the start. Links from
  separate files are placed with an offset when added, or with **Bookmarks ▸ Align Links on
  Bookmark Pair…** from one bookmark on each Link at the same event. Changing an offset
  re-decodes nothing.
- Four pane groups each show a Link of their own, chosen by a picker in the group: the
  Commands table, Registers with Statistics, the Bus Grid, and Capture with CDS, Audio,
  Samples and Timing.
- **All Links** in the picker of the signal panes (Capture, CDS, Audio, Samples and
  Timing), or **View ▸ Links ▸ Signal Panes: All Links**, shows every Link at once: one pane per
  Link, stacked, on shared time. Zoom one Capture or Audio pane and the others follow, and
  each Timing pane keeps its own region, filter and edge colours. Going back to one Link
  gives the panes back their one-Link height. The Bus Grid keeps one Link at a time.
- Every group follows the one cursor, at the same instant on its own Link. A pane's menu
  acts on that pane's Link.
- **All Links** in the Commands pane (its picker, or **View ▸ Links ▸ Commands: All Links**) lists
  every Link's commands in time order with a Link column. The Timeline stacks one band per
  Link on one time scale.
- Bookmarks belong to the Link they are placed on and are drawn only on it. Clicking a
  Link's Timeline band makes it the Link the next bookmark goes on, so a bookmark on each of
  two Links gives the time between events on two buses. The Bookmarks pane names each
  bookmark's Link.
- A pair across two Links shows rows (or UIs) only when both Links run the same row (or UI)
  rate for the whole time between the bookmarks; where either changes in between, that count
  is not shown. On one Link, rows and UIs between two bookmarks are counted exactly, including
  across PHY3's change from Safe-Lock to the full column count.
- Workspaces record every Link with its name, offset and the pane layout. A workspace saved
  by an earlier version opens as one Link.
- With a single Link, everything looks and behaves as before.

## Demo captures

- The Bus Analyzer no longer decodes a demo capture when it is first entered. With nothing
  open, its panes are empty and say so, pointing to **File ▸ Open Capture…** and **File ▸
  Open Demo Capture**.
- **Open Demo Capture ▸ PHY2 (Two Links)** opens the PHY2 demo and the flow-control demo as two
  Links, as one analyzer would record both buses, the second starting about 2.47 ms later.
  It is the same pair the multi-Link tests run on.
- The PHY1, PHY2 and PHY3 demo captures now carry **DP0 at 44.1 kHz using payload interval
  skipping** (Section 14.1.10) on 48 kHz transport opportunities: 13 of every 160 intervals are
  skipped. 44100/48000 is exactly 147/160, so the rate is exact rather than approximated, and 160
  is the smallest denominator that expresses it. DP1 remains at 48 kHz, so each demo shows a
  mixed-rate bus.
- DP0 is the unscrambled port, chosen so a mis-phased skip shows up as a wrong sample value
  rather than as descrambler noise.
- The flow-control demo is unchanged: its ports already gate transport on DRQ/SourceReady, and
  skipping would confound two separate reasons for an interval to carry nothing.
- A consequence worth knowing if you write tests: a skipping port's legal sync-point rows are
  Interval x SkippingDenominator apart, so the periodic-SSPA alignment rises from 64 rows to
  10240. A demo region shorter than about 160 samples per channel can no longer hold an
  interval-aligned SSPA and gets none.

## Captures without a bring-up

- A capture that starts after the bus is already running (a recording joined mid-stream)
  no longer shows a bring-up it does not have. It used to be read as a Cold or Warm Start
  on PHY1 and PHY2, which drew invented bring-up phases on the Timeline and swapped the
  DP and DN labels in the Capture pane. The decoded commands were never affected.

## Timeline

- Zooming and panning the timeline stays quick however many commands a capture holds. It
  used to slow in proportion to them: about a tenth of a second per wheel step at 100,000
  commands, now a few milliseconds.
- Dragging the cursor along the timeline now ends exactly where the button is released. It
  could stop a few pixels short, at the last position the pointer reported while moving.

## Light mode

- Audio waveforms, bookmark lines, the Capture pane's per-port bit marks and the Samples
  pane's Port column are now readable on the light theme. They used the Bus Grid's pale
  cell colours, which almost vanish on a white plot. Each stream keeps its hue, so it still
  matches its Bus Grid colour, darkened for the light theme. The Bus Grid itself is
  unchanged.
- The plot gridlines in the Audio, Capture and Timing panes are clearer, in both themes;
  on the light theme they had faded almost to white.
- Launching in light mode no longer shows the Capture pane's traces, cursor and commit
  markers in the dark theme's colours until the theme is switched.

## Waveform colours

- **View ▸ Waveform Colors and Line Weight…** (Ctrl+,; on macOS, ⌘, opens it as
  **Preferences…** in the application menu) sets the line colours for each theme: data
  ports, bookmark pairs, the Capture traces and the Timing edge colours, and how thick the
  Audio and Capture lines are drawn (1 to 4 pixels). A colour that would be hard to see on
  that theme's background is marked, and still allowed.
- Right-click a stream's checkbox in the Audio pane to give it a colour of your own. It is
  kept for that Link and that theme, shows in the Capture and Samples panes too, and is
  saved in the workspace. A colour belongs to the data port, so all of that port's channels
  take it.

## Panes

- The Audio and Capture panes drop their "Time" and "Amplitude" axis titles, giving the
  traces the room. Audio's amplitude axis now shows -1, 0 and +1 (only 0 used to fit), and
  under Vertical Zoom the extremes of what is shown, in plain numbers.
- Every Link picker shows a drop-down arrow, as the Commands one does.
- The Timeline's Link names take only the room they need, so the bands start further left.
- The Samples pane's Decimal column is as wide as its numbers, so stacked Links' tables
  match.

## Menus

- **Mode** is the first menu, and every menu shows only what applies to the current mode.
  The Bus Visualizer and Timing Calculator show Mode, File, View and Help; File holds only
  that mode's files.
- **⌘O / ⌘S** (Ctrl on Windows and Linux) open and save the current mode's file: a capture
  and the workspace, a Visualizer CSV, or the timing settings.
- **File ▸ Open Capture…** shows one page before anything is decoded: what the file is
  (format, channels, sample rate, its length, and whether all of it fits in memory), its
  Links (a name, a clock and a data channel each, with edge counts; add several from one
  file), how much to decode (all of it, or from and to a time, with the cost shown), and
  whether to replace the open Links or add to them, with an offset. It replaces the
  separate clock and data prompts, the "take another Link?" question, the start-and-length
  prompts for a large `.sal`, Open Capture Time Window and the analog CSV dialog. Every
  format can now be windowed, and a workspace reopens the window. A file holding several
  Links offers them pair by pair (channels 0 and 1, then 2 and 3), the busier of each pair
  as its clock. Edge counts are rounded (~9.8M, ~163k), and the window is entered in s, ms or µs
  to suit the capture's length.
- **The Links menu is gone.** A Link is named and added in Open Capture; Rename, Set Offset
  and Remove are on its timeline label's right-click; *Align Links on Bookmark Pair…* is in
  Bookmarks; the All Links toggles and *Link 1…9* are in **View ▸ Links**, with the same
  shortcuts.
- **Locate Sub-Capture** picks its reference's signals, and optionally a window of it, in
  the same dialog.
- A new **Decode** menu holds everything that re-decodes the capture: Import Visualizer
  CSV, Force Column Count, Hub Depths, the Per-Dataport Scrambler, Manual SSP Move and
  Block PDM DC Bias. **Audio** keeps playback and Export Audio as WAV.
- Items that act on a capture are greyed out until one is open, instead of opening a
  message.
- A slim **status bar** is back along the bottom of the window. The messages it shows (a
  capture opened as a Link, an offset set, a filter that found nothing) had been going to
  a hidden label.
- **Commands ▸ Filter ▸ Commands** gains **None** and **Commit** (the SSCR / DSCR commits
  and the Commit Point rows where they take effect), and its quick picks have keys: All
  ⌘4, None ⌘5, All excl. Ping ⌘6, Commit ⌘7 (Ctrl on Windows and Linux).
- Renamed: *Open / Save Visualizer CSV…*, *Export Grid Image…*, *Export Bus Model
  (JSON)…*, *Open / Save Timing Settings…*, *Device Names…*, *Peripheral Register Maps…*,
  *Hub Depths…*, *Signal Panes: All Links*.
- **Help ▸ SWI3S Studio User Guide** opens the User Guide in a window, which closes with the
  application; **Help ▸ About SWI3S Studio** shows the version.
- On Windows and Linux, **Ctrl+Q** quits and **Ctrl+,** opens Preferences, and Keyboard
  Shortcuts writes the keys as Ctrl+Alt+Shift+0 rather than with Mac symbols. On those
  platforms View has one item for the waveform settings, *Waveform Colors and Line Weight…*, rather than two
  that open the same dialog.
- **Help ▸ Keyboard Shortcuts** lists the Bus Analyzer's keys, the waveform settings' among
  them, in the Bus Analyzer only.

## Large captures

- Free memory is now read through a per-platform standard-library route when `psutil` is
  absent. Previously only Linux had one — Windows has no `sysconf` and macOS does not publish
  `SC_AVPHYS_PAGES` — so an install without `psutil` fell through to the unknown-memory
  fallback silently, and that fallback was far too permissive on exactly the machines least
  able to absorb it (8.59 GB allowed where a real reading gives 2.40 GB on a 4 GB machine).
- When free memory cannot be read at all, the budget degrades in documented steps — free RAM,
  then a quarter of total RAM, then the same rule against a pessimistically small assumed
  total — and a degraded tier is reported in the log rather than silently using a fixed figure.

## Command line

- `-o FILE` / `--output FILE` writes the bus model to JSON and implies headless mode: no window
  is opened, and Qt is not imported at all, so it runs where there is no display. Restores the
  v2 batch entry point, absent for the whole v3 line.
- `-c FILE` / `--config FILE` names the input configuration CSV. Without `-o` it opens that CSV
  in Bus-Visualizer mode; `-o` requires it.
- `--help` lists every option, and the `usage:` line names the command you actually typed —
  `./run.sh`, `.\run.ps1`, `swi3s-studio` or `python -m swi3s_studio.app` — rather than a
  fixed name that is only correct for one of them. There was previously no argument
  parsing at all.
- The JSON is byte-identical to **File ▸ Export Bus Model (JSON)…** in the Bus Visualizer,
  and the printed issue list is the same one the notifications panel shows.
- Exit codes: 0 clean, 1 error (no model written), 2 model written but it contains a bus clash
  or a truncated DRQ.
- The `run.sh` / `run.ps1` launchers now forward their arguments to the application. They
  previously discarded all of them, so `./run.sh --demo` opened an empty window and
  `./run.sh -c cfg.csv -o out.json` started the UI without writing a file. `run.ps1` also
  propagates the exit code.

## Publishing and documentation

- Each release is described once, in `docs/releases/vX.Y.Z.md`: a tracked file, so it is in
  the tag and in the release diff, and the leak scan covers it.
- Published prose follows a written rule, `docs/DEVELOPMENT.md` "Write the RULE, not the
  story": no discovery narrative, generalise the artifact, generalise the finding, keep the
  measurement.
- `tools/leak_scan.py --text=<file>` scans text that ships but is not a file, such as a
  branch description.

## Checks that could report a pass without looking

- The leak scan ignored an unrecognised option, fell through to a working-tree scan and
  printed "no leaks found" about input the caller never named. It now exits 2, as it does
  for a named file that does not exist.
- The leak scan's self-exemption was per file where it belongs per pattern kind, so its own
  files escaped the site-specific patterns too. They now reach them.
- The mypy ratchet read no errors at all where the environment forces coloured output (the
  colour codes hid every error line), and passed. It now asks mypy for plain output, and
  refuses a failing run it could not read.

## Tests

- `visualizer_examples/directed_tests/README.md` names the example configurations that
  report errors or warnings because they exercise the Visualizer's checks, and a test keeps
  the list equal to what the engine reports.

- The timeline's zoom, pan, seek and bookmark drag are tested with real input events, and
  zooming one Link's band is checked to show the same instants on every other.
- The dialogs (Open Capture, audio export, Visualizer CSV, register map, Link offset) are
  tested by filling them in through their own controls. A test that opens a dialog it does
  not handle now fails, where offscreen it used to wait forever.
- Warnings from the application's own code, and files left open, fail the suite, as does
  an error raised inside a Qt signal handler (which the toolkit only prints). Tests keep
  their settings in a throwaway file and close the windows they open.
- A plain `pytest` runs the functional suite; the timing ceilings run on their own
  (`pytest -m perf`), as the gate and CI already ran them. Run together they could fail.
- `tests/run_all.sh` is now a wrapper over the gate's per-suite check, so the two cannot
  drift apart. `docs/TESTING.md` names every test suite, which a test now checks.
- CI's coverage floor rises from 75% to 80%; the suite measures 85%.
