# SWI3S Studio v3.0.9

Flow control (TX_PRESENT, DRQ, FCP) end to end, a framing fix that applies to every capture,
and Visualizer handover corrections.

## Flow control

- **Demo capture: Flow Control (4 modes).** Four peripheral data ports, one per flow mode
  (NORMAL, TX_CONTROLLED, RX_CONTROLLED, ASYNC). The audio is sampled uniformly and the
  transport is jittered on a 2x-oversampled opportunity grid.
- The decode gates on TX_PRESENT: a sample is emitted only when its TX_PRESENT bit reads 1, so
  gated transport decodes back to a bit-exact stream. The descrambler LFSR still advances on
  skipped opportunities.
- The FCP is re-driven during decode to read DRQ off the bus and validate the DRQ↔TX_PRESENT
  handshake (§14.2.2: RX bijective, ASYNC carries data only when requested) with the
  d = FlowControlDelay+1 pipeline. Results are in `Decoder.flow_control_stats()`.
- The Bus Grid draws DRQ and FCP guard and tail cells: a wide SOURCE DRQ drives every UI, a
  wide SINK DRQ occupies only its last-UI sample point.
- The audio waveform draws a flow-controlled stream at its measured average rate.
- Native ABI 6 → 7: `AudioSample` gains `flow_mode` and `drq_sample`.

## Decode

- A K.28.7 SPM detected mid-phase no longer reframes or abandons the phase. Per §7.2.2 and
  §8.2.1 an SPM only arms header detection; mid-phase framing is held by counting bits mod 10,
  so a payload byte or CRC that spells the comma at a sub-symbol offset no longer drops the
  command.

## Visualizer

- A handover onto another device's SINK bit is not a bus clash: only a SOURCE driver clashes.
- Sink data ports in RX_CONTROLLED and ASYNC draw their DRQ-driven handover.
- TX_PRESENT is present in RX_CONTROLLED as well.

## Tests and tools

- A bit-exact flow-control round trip in all four modes, with grid and handshake checks.
- Cross-engine parity (Visualizer engine against the native core) over the whole example
  corpus, FCP placement included.
- Visualizer round-trip tests, and a statistics report runner (`tools/viz_report.py`).
