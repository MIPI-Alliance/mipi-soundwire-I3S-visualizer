# SWI3S Studio v3.0.17

Adds support for Saleae `.sal` internal blob version 4, and corrects the large-capture memory
guard together with three per-interaction performance defects.

Gated on every supported platform before tagging.

## Ingest

- Logic 2 `.sal` digital blobs at version 4 open. The format is version 3's with a new
  version number, so they decode through the same reader.
- Accepted blob versions are 0, 3 and 4, pinned by a test. Any other version is refused with a
  clear error.

## Large captures

- The predicted peak memory of an open applies the decode transient to the edge-array term.
- The memory budget is the lower of a fraction of free memory and an absolute ceiling.
- **Analyzer > Open Capture Time Window...** opens a chosen start and length of a `.sal` at any
  size.
- A windowed open costs the window rather than its start offset.

## Performance

- The Decoded Samples pane holds a smaller window, so a cursor move that leaves the loaded
  range rebuilds fewer table items. A move inside the range rebuilds none.
- TX-map persistence scans above a size threshold run on a worker thread instead of the GUI
  thread.
- Extending the Decoded Samples window no longer triggers a second load at the opposite end.

## Tests

- Per-cursor-move cost is asserted as deterministic counts — rows built, which thread a region
  scan runs on, hidden panes doing no work — alongside wall-clock ceilings.
- The memory prediction is checked against a measured load.
- Version 4 coverage is parametrised over both versions and asserts they decode identically.

## Not in this release

The per-platform standard-library route for reading free memory, and the tiered fallback for
when it cannot be read at all. Both ship in 3.0.19.

## Differences from the release tag

The published tree is not byte-identical to `v3.0.17`. Two differences are not derivable from
the tool that assembles it:

- **Nine files of prose.** In eight — comments, docstrings and documentation, no product code —
  prose about the development environment is generalised. Every measurement is unchanged, the
  changelog carries the 17 entries the tag carries, and `__version__` is 3.0.17. The decode
  core, the reference model, the UI and every assertion are byte-identical.
- **This file.** It postdates the tag; a tree built from the tag alone does not contain it.

The publish branch is assembled by `tools/publish_tree.py` from a single recorded source
commit.
