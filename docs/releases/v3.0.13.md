# SWI3S Studio v3.0.13

The Timing page models a mixed SWI3S / SoundWire 1.3 bus with 17 numbered inequalities in
physical time order, EndDriveEarly and a bus keeper leg, and click-to-trace terms. The
Visualizer gains per-device CDS drive type and end-drive-early, carried to and from the
Analyzer (`score_abi` 10). Payload interval skipping decodes the right intervals, and a new
Statistics section shows what each peripheral reports about itself.

## Timing page

- **A mixed bus.** The Manager and the Peripheral are each set to SWI3S PHY1, SWI3S PHY2, or
  SoundWire 1.3 at either supply, and contribute the timing their own spec states.
  `timing/spec_source.py` puts each side's clock-to-output on the common pure-delay basis the
  inequalities use. A SoundWire side shows its f_Clock ceiling and the cost of receiver
  hysteresis it does not guarantee. The PHY1/PHY2 picker is folded into the per-side spec
  selector.
- **17 inequalities, numbered 1) to 17)** in display order, on the equation rows and in
  `summary_text()`, from one map (`_INEQ_NUMBER`). They cover Manager-to-Peripheral,
  Peripheral-to-Manager and Peripheral-to-Peripheral setup and hold in both launch forms, three
  handover non-contention legs, and one bus keeper leg per releasing device.
- **Physical time order.** Every leg's terms read in the order the events happen, with the
  receiver's window (t_IS or t_IH) last.
- **Headings name the obligation:** "Manager Setup for Peripheral", "Manager Holding for
  Peripheral", "Peripheral Setup for Manager", and so on; "Bus Keeper — Manager Releasing" and
  "Bus Keeper — Peripheral Releasing".
- **Click a term to trace it.** Clicking a symbol or substituted number highlights every
  occurrence of the same parameter across all 17 inequalities, in the equation and the
  Specification/Example rows, and washes its input row. Click again, or on blank space, to
  clear. Several may be lit at once. The key is the input row: `Man_t_DD,pure` and `Man_t_DD`
  are one key, and a crossing keys on its t_RF lane.
- **Peripheral-to-Peripheral setup and hold**, each with its t_ZD launch variant. A drives and
  B samples on every P→P leg, enforced by a test. The P→P placement selector has four
  layouts, including both peripherals far; "Worst Per Leg" bounds an unknown placement (saved
  as `unknown`).
- **Handover non-contention** on MP, PM and PP:
  N_HO·UI + t_ZD,min(acquiring) − t_DZ,max(releasing) + clock skew ≥ 0. Each device's
  parameters are referenced to its own clock.
- **Handover UI checkbox** selects whether the N_HO·UI term applies, seeded from the selected
  PHYs and overridable both ways (§11.1.1.1). With no handover UI allocated, no UI term is
  shown.
- **EndDriveEarly** is a selectable spec source (SWI3S PHY2 EDE), modelled as a negative
  effective t_DZ through per-side `Man_ede` / `Per_ede` flags. Selecting it compares PHY2
  Proposed (baseline) with EDE Proposed (candidate), and the column headings follow. Four EDE
  rows are UI fractions and follow F_CLK. Table 130 bounds the EDE release: the release is
  the latest legal point the launch grid can place (`ede_release_ceiling_ns`), annotated
  when it moves.
- **Bus keeper leg:** release_earliest − t_DD,max ≥ Man_tKeeper_Response (3 ns, Table 125),
  charged on every keeper leg.
- **Manager launch mode** (analog, 2× or 4× clock) sets the clock's resolution. Man_t_DD,
  Man_t_ZD and Man_t_DZ are all clocked or all analog, are editable placements snapped to the
  selected grid, and a snap is reported in the term's note. Labels read "4× CLK (1/4 UI
  grid)".
- **Receiver thresholds stay windows.** V_IH and V_IL keep both ends in force
  (`CalcRow.is_window`).
- **Measurement anchor.** Per_t_DD and Per_t_ZD are measured to 20% of the ramp (Figure 174);
  the pure-delay back-out uses the t_RF of the spec's reference test condition, not the slew
  in force.
- One clock pin has one slew: legs that read `Man_t_RF,CLK` twice take both at the same corner.
- One Man_t_DZ is read by both the keeper and the contention legs.
- The threshold fractions `V_OH_frac` / `V_OL_frac` set the swing in every crossing term.
- The Specification column shows the current spec, read-only; the editable Example column
  seeds from a proposed revision.
- **Defaults:** F_CLK opens at 12.288 MHz (256 × 48 kHz), clamped by what the selected pair may
  clock; bus length is 0–30 cm.
- **Notation:** every t_RF lane is qualified (`Man_t_RF,CLK`, `Man_t_RF,DATA`); a crossing reads
  `X_<pair>,<role> · <lane>_t_RF` with the role `late` or `early`; multiplication is the
  middle dot; the swing term's t_RF is explicit in the substitution row (`1.67·8.30`). The
  style rules are tests.

## Bus Visualizer

- **CDS drive type and end-drive-early, per source.** CDS_DriveType (0x86 bit 7: 1 Normal,
  0 Special) and CDS_EndDriveEarly (0x87 bit 4: Full / Early) are 13-entry lists on the guard
  and tail's index convention (0 = Manager, i = Device i-1), in both CSV engines as
  `CDS_DriveTypePerSource` and `CDS_EndDriveEarlyPerSource`. A file without them loads with
  the defaults (drive type Normal, end-drive-early Full).
- **The CDS cell is two lines:** `CDS` over a flags line (`SP`/`SPx`, `EDE`/`EDEx`, `x` meaning
  the sources disagree). Only the CDS column widens to fit, and only when there are flags.
- **CDS Settings** is one row opening a dialog: bus-wide bit width and Enforce CDS Handover,
  then per-source guard, tail and drive type, with an "All sources" strip. Nothing commits
  until OK. The summaries elide, with the full text in the tooltip.
- **The CDS crosses to the Analyzer both ways** (`score_abi` 10): an authored config emits
  0x1186 and 0x1187 per device, and a decoded capture's snooped writes rebuild them, so its
  exported CSV keeps its CDS. The Manager's slot stays at its default.
- **DP colours key on the config slot.** Cells carry `dp` (the logical DataPortNumber, in both
  engines) and `dp_index` (the slot); the grid colours by slot, and the key names each port
  ("Mgr·DP0", "D1·DP0") when it has no name.
- **A Manager data port is read the same in either row order.** `ManagerDataport` is resolved
  after the CSV is parsed, in both engines.

## Decode

- **Payload interval skipping (§14.1.10)** starts its accumulator on the interval that begins
  at the SSP, matching `Initialize()`.
- A skipping port's pattern repeats every Interval × SkippingDenominator rows (§4.2.3.1); the
  manual-SSP row reduction and the demo SSPA cadence use `SwI3sConfig::patternRows`.
- **New error:** an SSP while a skipping port is part-way through its pattern is an unexpected
  SSP (§9.1.6.2.1), reported on the command that generated it.
- The native CSV reader decodes the Manager data port (device 0 plus `ManagerDataport`), so its
  configuration is no longer emitted as register writes to device 0.
- The demos carry an immediate read and a deferred read.

## Statistics and registers

- **Peripheral Reports:** what each device reports through its IntStat_* / DevStat_* bits and
  EC_* counters. Faults and ImpDef/SDCA interrupts are top-level rows and count as Commands
  errors; live state folds per port. A reply that failed CRC is ignored.
- Per-command statistics fold a deferred read into one logical read.
- Statistics ▸ Regions leads with the bus configs.
- **Register arrays** from the spec tables expand to one register per address with numbered
  fields; Reserved and ImpDef filler runs stay one row showing their address range
  (`RegisterSpec.span`).
- The register map is re-extracted to spec revision r08, keyed on name, block, offset and bit
  range.

## Memory

- The demo capture is not decoded at startup.
- The decode's native audio vector is released once the session has copied it.
