# SWI3S Studio v3.2.0

The Timing Calculator places every edge by its 20 % point and measures the Manager from its
clock output, evaluates each setup, hold and contention inequality on either clock polarity,
and searches the slews, τ, α and δ together for each margin's worst corner. F_max is the first
failure as the clock rises and stops at the toggle ceiling. It models a Manager that forces its
keeper, gives the EndDriveEarly release an EDE Delay per side, and offers SoundWire 1.3 at 1.2 V
with its SWI3S equivalents. Every term of every inequality has a diagram, drawn for reading
at a distance, and a maximized diagram can show the Specification column, the Example column or
both. DPn_PortMode 2 is now Test0 and 3 is Test1, as the specification's table defines them: a
file saved by an earlier release keeps its number, so swap 2 and 3 in `PortMode_REG` to keep
the pattern it drew (below). A flow-controlled port's DRQ history carries across a config
commit, the importers bound what they read and report what they skipped or changed, and the
save dialogs ask before an added extension replaces a file.

## Changes

- **DPn_PortMode 2 is Test0 and 3 is Test1**, per the "Effect of DPn_PortMode" table: in Test0
  every Channel, TxPresentCh and FCP DRQ bit is raw 0, in Test1 raw 1. The Bus Grid draws a PortMode
  2 port's channel bits as `T0` and a PortMode 3 port's as `T1`, and the Port Test Mode dialog's
  buttons read Test0 (0s) and Test1 (1s) and write 2 and 3. Earlier releases drew a PortMode 2 port
  as `T1` and a PortMode 3 port as `T0`, and their dialog wrote 2 for Ones and 3 for Zeros; the
  Registers pane already read 2 as Test0 and 3 as Test1. A Visualizer config CSV or workspace saved
  by an earlier release keeps its number, so a saved 2 now draws Test0 and a saved 3 Test1: swap 2
  and 3 in `PortMode_REG` to keep the pattern the file drew. The shipped `test_mode_ones.csv` and
  `test_mode_zeros.csv` carry 3 and 2.
- **The Bus Visualizer's scrambler square sits in its own bit's top-left corner.** It was drawn one
  column to the right, where the next cell covered it, so a run of scrambled bits showed one square,
  outside the run's last cell.
- **The Bus Visualizer's grid has a ⤢ at its top right**, as a pane does: it, Maximize Frame and
  View ▸ Maximize Pane (Ctrl+Shift+M, ⌘⇧M on macOS) give the grid the whole page and put the parameters back. Dragging the
  parameters shut maximizes it too, and it stays maximized across a mode switch. It replaces the
  Show Parameters button.
- **A write to a CDS register's read-only _CURR alias shows as not applied** in Register History, in
  both the _CURR and the _NEXT history, with the status "read-only _CURR alias: no effect", as the
  Registers pane already treated it.
- **A workspace whose saved cursor is not a sample opens at sample 0**, and one whose saved mode is
  not text opens in Analysis, each with an import note, instead of failing to open. A saved cursor
  is clamped into the active capture on open.
- **An analog capture whose time axis has NaNs gets its sample rate from the valid steps** instead
  of falling back to 1 MHz.
- **Times on no sample grid give a rate**: the reciprocal of the finest spacing to 4 significant
  figures, at least 1 Hz, so a spacing of 2 ms or more no longer reads as having none.
- **A Link restart before a rejected first bring-up's audio start is found**: the later bring-ups
  are searched from the first one as the decode validated it.
- **A flow-controlled port's DRQ history carries across an SSCR that changes its config.** The
  startup intervals, whose TX_PRESENT takes DRQ 1, count from the Source DP's enable ({ASW5204},
  Table 160 (v1.1 r10)), so the decoder checks the first intervals after such an SSCR on an
  RX_CONTROLLED or ASYNC port that stays enabled against the DRQs sent before it, as it does after a
  DSCR. A port enabled again, a FlowMode change that gives the port its DRQ, an SSP that moves the
  port's interval phase, or a commit that lands part-way through an interval starts the history afresh.
- **The Timing Calculator's EndDriveEarly release is an EDE Delay, per side.** A side on the EDE
  source holds its level for its **EDE Delay** (3–7 ns, a new Handover Timing row per side) after
  its ramp reaches 80 % and then goes high-Z: the release is at t_DD + t_RF + EDE Delay from the
  edge that opens the driven UI. The Manager and the Peripheral each use it when their side is on
  the EDE source. A contention leg shows the latest release as its parts in time order, the
  releaser's t_DD, its ramp to 80 % and its EDE Delay, then the UI back to the closing edge, so a
  click on the t_DD, t_RF or EDE Delay row highlights them; each keeper leg reads EDE Delay,min and
  the ramp to V_OH / V_OL, less the data's crossing of the keeper's threshold and
  Man_tKeeper_Response. The 0.60·UI + 10 ns release ceiling and the peripheral's hold interval are
  removed.
- **The Peripheral's Bus Keeper inequality counts from its own two clock detections.** keeper_Per
  counts Per_t_DD from the Peripheral's detection of the edge that opens the UI and Per_t_DZ from
  its detection of the closing edge, of the other polarity, so it carries the spacing of the two
  after the closing UI: `−(X_MP,rise,late − X_MP,fall,early)·Man_t_RF,CLK`, the opening edge detected
  late and the closing edge early, at the Peripheral's one supply. The leg is evaluated with the
  closing edge rising and falling and reports the worse. The keeper rule below gives its values on the
  default page.
- **The Bus Keeper inequalities are measured at the Manager's V_IH / V_IL, per the Bus Keeper
  table.** Man_tKeeper_Response is the Manager's requirement, measured from the keeper's input
  crossing V_IH / V_IL, and the keeper's input is at the Manager. Each keeper leg counts the
  response from the releasing data's crossing of the Manager's V_IH,max (rising) or V_IL,min
  (falling) at the Manager's supply, `X_K,rise,late` / `X_K,fall,late · <dev>_t_RF,DATA` after the
  launch's 20 % point, a
  Peripheral's data swinging to its own supply and offset by the ground shift α. The release is
  1·UI + t_DZ for a conventional release and t_DD + the ramp to V_OH / V_OL + EDE Delay with
  EndDriveEarly; the level and the high-Z reach the Manager one flight later, so no t_PD term
  enters. On the default page keeper_Man reads +9.40 ns (Specification) and +4.40 ns (Example)
  and keeper_Per −1.93 and +9.07 ns; on the EDE Proposed column keeper_Man reads +0.75 ns and
  keeper_Per −0.33 ns, where the Peripheral's data crosses V_IH,max + α after V_OH. A SoundWire
  Manager's keeper takes its own thresholds (below). The term diagram counts the response at the Manager from the
  data's crossing of the threshold line, and draws keeper_Per's data at both pins.
- **Output timing holds at every rise/fall time of its ramp setting.** A t_DD or t_ZD is the instant
  its ramp reaches 20 %, at any t_RF from 3.0 to 8.3 ns for the 5 ns setting, and each inequality
  charges only the ramp after that point. At the slow end of the setting a peripheral-launched setup
  leg gains 1.10 ns and at the fast end a hold leg 0.67 ns (0.53 and 0.32 on an exponential ramp).
- **The Manager's timing is measured from its clock output's V_OL / V_OH crossing**, 1/3 of its
  clock t_RF after the clock starts on a linear ramp (0.161 of it on an exponential one), for t_DD,
  t_ZD, t_DZ, t_IS and t_IH alike, as the Manager Output and Input Timing figures draw it. P→M setup
  gains up to 2.77 ns and P→M hold loses up to 1.00 ns, M→P contention loses up to 1.00 ns, and P→M
  contention gains up to 2.77 ns. A contention leg takes the acquiring driver's turn-on at its 20 %
  point.
- **The per-edge slew tolerance applies to the whole edge and keeps it inside its range.** A lane's
  two edges ramp at its t_RF times (1 ± τ), and no edge leaves its spec's range: at 8.3 ns the late
  edge stays at 8.3 and the early one takes the whole 2τ mismatch and is faster by 2τ (10 % at τ = 5
  %), at 3.0 ns the early edge stays at 3.0 and the late one is slower by 2τ.
- **Every edge is placed by its 20 % point, and the UI runs between clock references.** The UI is
  the time between two consecutive Manager clock references, its V_OL / V_OH points, and one clock
  edge's references at two pins are a flight apart, whatever each ramp's slew. A crossing
  coefficient counts from its edge's 20 % point, so a crossing term reads `X · t_RF`: the ramp from
  that point to the receiver's threshold. The legs whose two clock events sit on edges of opposite
  slew factor gain f_A·(t_RF,late − t_RF,early), where f_A is the ramp before the 20 % point (1/3 on
  a linear ramp): M→P, P→M and P→P setup, and P→P hold and contention where their two clock
  detections are of two edges, 0.28 ns at their worst corners. The other legs are unchanged. The closed-form 2x
  limit, `launch_mode_max_fclk_MHz`, reads 25.1 MHz.
- **Two peripherals detecting one clock edge take one slew factor.** On P→P hold, and at zero
  handover UIs on P→P hold with a handover and on P→P contention with a conventional release,
  Peripheral A's and Peripheral B's clock detections are of one Manager clock edge. Both take that
  edge's one slew factor, (1 + τ) or (1 − τ), whichever leaves the inequality the less margin, and
  each keeps its own crossing coefficient; detections of two edges keep their own factors. A
  detection on an edge whose factor is not its corner's own names the edge in its symbol, e.g.
  `X_MP,A,rise,slow,early` and `X_MP,B,fall,slow,early`. On the Timing Calculator's default page,
  which shows
  each inequality at its worst corner, P→P hold gains 0.20 ns; at the nominal corner of the default
  inputs it gains 0.12 ns, as do P→P hold with a handover and P→P contention at zero handover UIs.
  The term diagram draws the shared edge with one t_RF at A and at B.
- **One device has one supply.** Each inequality is evaluated with the Manager, the Peripheral and,
  on P→P, Peripheral B each at one V_SEOS extreme, every crossing taking its transmitter's supply
  for its ramp and its receiver's for its threshold, and keeps its worst assignment. A device's two
  crossings in one inequality no longer sit at opposite supply extremes. At the reference
  cross-check's matched configuration (`docs/anchors.md`, "The supply split") it moves P→M setup by
  1.75 ns, P→P setup by 0.99 ns, P→P hold and contention by 0.43 ns, and M→P contention and
  P→P contention with a releasing EDE peripheral by 1.05 ns; the other inequalities are unchanged.
- **Every setup and hold inequality samples on either clock polarity.** M→P, P→M and P→P setup and
  hold, with and without a handover, are each evaluated with the sampling edge rising and falling
  and report the worse case. The launching edge follows from the sampling edge: the other polarity
  on setup, the same edge on hold, and on a handover leg the edge its handover count gives after it.
  Every detection is at its polarity's corner, V_IH on a rising edge and V_IL on a falling one, and
  a late crossing pairs with an early crossing of the other polarity under one ground shift. Each
  crossing's symbol names its edge's polarity (see "A crossing symbol names its direction and its
  edge" below). The term diagram draws the polarities in force. In the default window, symmetric about mid-rail, the two polarities give one
  margin at equal supplies. At the defaults PM_hold_ho reads 49.66 ns; with the Manager's clock at
  t_RF 8.3 ns PM_hold reads 7.97 ns and PM_hold_ho 50.06 ns. In a window not symmetric about
  mid-rail, V_IH 0.40–0.65 and V_IL 0.35–0.50, MP_setup reads 7.36 ns, MP_setup_ho 15.36 ns, MP_hold
  −2.23 ns, MP_hold_ho 34.86 ns, PM_hold_ho 49.74 ns, PP_setup −3.30 ns and PP_setup_ho 6.70 ns.
- **Every contention inequality closes on either clock polarity.** MP_contention, PM_contention and
  PP_contention are each evaluated with the edge that closes the releaser's UI rising and falling,
  and report the worse case. A releasing peripheral detects that edge late, at V_IH,max + α rising
  (`X_MP,rise,late`) or V_IL,min − α falling (`X_MP,fall,late`); under EndDriveEarly it detects the edge
  that opens its UI, of the other polarity. The acquirer turns on after the edge its handover count
  gives, the closing edge's polarity at an even count and the other at an odd one, PHY2's one UI
  included, detected early at V_IH,min − α (`X_MP,rise,early`, `X_MP,B,rise,early`) or V_IL,max + α
  (`X_MP,fall,early`, `X_MP,B,fall,early`). In the default window, symmetric about mid-rail, the two
  polarities give one margin at equal supplies. At the defaults MP_contention reads 38.78 ns,
  PM_contention 28.63 ns and PP_contention 29.32 ns; with the Manager's clock at t_RF 8.3 ns they
  read 39.17, 25.46 and 26.54 ns. In the window V_IH 0.40–0.60 and V_IL 0.30–0.50 with the
  Peripheral's data at t_RF 6.0 ns they read 38.62, 28.63 and 29.16 ns. On the Example column with
  both sides on SWI3S PHY2 EDE, MP_contention reads 1.40 ns and PP_contention 6.77 ns.
- **Σ_cross,PM,setup takes data of either polarity.** Besides the data on the launching clock edge's
  polarity, P→M setup evaluates a rising clock with falling data and a falling clock with rising
  data, each crossing at its own polarity's late corner. The ground shift that delays the clock
  crossing then delays the data crossing too, so it does not cancel, and the worst case is used.
  Both crossings carry the case's letters, the clock edge then the data edge: `X_PM,rr,late`,
  `X_PM,rf,late`, `X_PM,fr,late` or `X_PM,ff,late`. At the defaults PM_setup reads −3.43 ns and PM_setup_ho
  6.57 ns; with the Manager's clock at t_RF 8.3 ns −6.60 and 3.40 ns; in the window V_IH 0.40–0.60
  and V_IL 0.30–0.50 with the Peripheral's data at t_RF 6.0 ns −4.43 and 5.57 ns.
- **Σ_cross,PM,hold's same-polarity cases have their own symbols**, `X_PM,rr,early` both rising and
  `X_PM,ff,early` both falling, so `X_MP,rise,early · Man_t_RF,CLK` and `X_MP,fall,early · Man_t_RF,CLK`
  each carry one coefficient on every leg.
- **A crossing symbol names its direction, driver to receiver, and its edge.** A crossing reads
  `X_<pair>[,<device>],<edge>[,slow|fast],<role>`, and no polarity is implied by an unqualified
  symbol. Every Peripheral's lone detection of the Manager's clock is an `X_MP` crossing, with
  `A` or `B` on a P→P leg, and takes the symbol of the M→P clock crossing whose coefficient it
  carries: `X_MP,fall,early` and `X_MP,rise,early` on MP_contention's acquirer, keeper_Per's
  closing edge and P→M hold's clock lane outside its rr and ff cases, and `X_MP,B,fall,early`,
  `X_MP,B,rise,early`, `X_MP,B,fall,slow,early` and `X_MP,B,rise,slow,early` on P→P
  contention's acquirer, in place of `X_PM,fall,early`, `X_PM,early`, `X_PM,B,fall,early`,
  `X_PM,B,early`, `X_PM,B,fall,slow,early` and `X_PM,B,slow,early`. A single crossing names its
  edge, `rise` or `fall`, and both addends of a Σ_cross,PM sum the sum's case letters, clock edge
  then data edge, `rr` / `rf` / `fr` / `ff`: `X_MP,late` → `X_MP,rise,late`, `X_MP,early` →
  `X_MP,fall,early`, `X_K,late` → `X_K,rise,late` or `X_K,fall,late`, PM_setup's `X_PM,late` /
  `X_PM,fall,late` → its case's `X_PM,rr,late` / `,rf` / `,fr` / `,ff`, and P→M hold's lone data
  crossing `X_PM,early` → `X_PM,fall,early`. The P→P legs' clock detections are `X_MP,A,…` and
  `X_MP,B,…`, P→P contention's releaser included: `X_PP,A,late` → `X_MP,A,rise,late`, and
  `X_PP,B,early` on the clock → `X_MP,B,fall,early`, the symbol P→P contention's acquirer carries
  for the same coefficient. `X_PP,B,…` is A's data at B alone: `X_PP,B,late` →
  `X_PP,B,rise,late`. `X_PM` names a Peripheral's data crossing at the Manager and an addend of a
  Σ_cross,PM sum. No margin or F_max changes.
- **A SoundWire launch's anchor follows its side's ramp shape.** On an exponential ramp the 20 %
  point is 0.161·t_RF after low impedance, and the clock's 65 % and 50 % crossings are 0.596 and
  0.339 of its t_RF after its 20 % point.
- **The ramp to V_OH / V_OL names its edge**: it reads `<dev>_t_RF,DATA,rise` or `,fall`, the edge
  it is priced on, whether or not the two polarities differ (they differ on an exponential ramp at
  V_OH + V_OL ≠ 1), so one symbol shows one value on every leg, and a click on it highlights its
  t_RF DATA row. A ramp priced on the fast data edge reads `<dev>_t_RF,DATA,rise,fast` /
  `,fall,fast`, and its note says fast edge.
- **A SoundWire launch's anchor is placed on its own edges**: at V_OH + V_OL ≠ 1 a falling launch's
  anchor is placed on the falling ramp and a Manager's from the clock edge it launches on, and each
  leg takes the edges that leave it the less margin; at every level the term names its edges, a
  Peripheral's data edge as `Per_t_DD,anchor,rise` / `,fall` and a Manager's clock then data edge
  as `Man_t_DD,anchor,rr` / `,rf` / `,fr` / `,ff` (likewise t_ZD). Margins move only at such levels
  with a SoundWire side.
- **A SoundWire t_OV launch and an EndDriveEarly keeper leg are evaluated on the fast data edge
  as well as the slow one**, and each leg reports the worse, its crossing named `,fast,late`.
- **A clocked launch mode applies to a SWI3S Manager only**: a SoundWire Manager launches as
  tabulated, whatever the launch selector holds.
- **A threshold no ramp reaches is refused.** If noise, a supply corner or V_IH / V_IL puts a
  threshold at or beyond the transmitter's rail, the model names it, on both ramp shapes, instead of
  returning an infinite or past-the-ramp crossing time.
- **A launch is placed at its 20 % anchor.** The timing package exports `sw13_anchor_correction`
  (with `find_worst_corner_rows_all`) and has no `pure_output_delay`.
- **A fractional handover count takes the nearest whole count, a tie going up**, for every edge
  rule.
- **The proposed and EDE sources preset their tabulated t_ZD range** (Manager 9–23 ns, Peripheral
  2–9 ns).
- **Gathered clock-crossing symbols show a true minus sign** inside the bracket.
- **F_max follows the Timing Calculator's own placements under a clocked Manager launch.** When
  F_CLK changes, a clocked Man_t_DD, t_ZD or t_DZ keeps its UI fraction unless that falls below the
  row's tabulated minimum, where it takes the next grid point. Each leg's F_max is solved across
  those steps.
- **F_max is the first failure**: the lowest rate at which a leg fails as F_CLK rises from zero,
  FAIL where it fails at the lowest rates and — where it never fails. Across clocked placement steps
  a leg can fail, pass again and fail again; the F_max cell's tooltip names the higher rates at
  which it passes again, and the binding rate is the lowest F_max over the legs that bound the bus.
  On the Example column, PHY2/PHY2 at 12.288 MHz with 4x CLK, MP_setup and MP_setup_ho read 19.155
  MHz, keeper_Man 24.390 MHz, and MP_hold 12.167 MHz, the binding rate, passing again from 12.50
  MHz, where its Man_t_DD,min moves from 0.25 to 0.50 UI.
- **The worst-corner search finds a margin's least point inside the τ, α and δ ranges.** Each
  is sampled at quarters of its range around each inequality's worst combination and the least
  sample polished, so a margin that turns inside a range, or where one supply assignment's case
  hands over to another's, is no longer reported at a corner's larger value. A pick inside a
  range shows its value on the Corner line ("V_SEOS tol (δ) at 3.58 %").
- **The Timing Calculator can model a Manager that forces its keeper.** With **Manager forces
  keeper** ticked, the Manager loads its keeper with the level it drives, so its release waits
  for no keeper response and the Manager-releasing keeper inequality reads "does not apply" in
  both columns, the summary and the term diagram. No other inequality changes. The flag is saved
  with the page's settings and cleared by Reset.
- **The term diagram is drawn for reading at a distance.** Edges, levels, guides and dimension
  lines are heavy strokes that scale with the text, the labels are demi-bold at the diagram's body
  size (18 px, a little smaller in a narrow pane), and the colours are saturated, in both
  themes. The labels no longer fall to a 7 pt floor.
- **A maximized term diagram can draw one column**: buttons beside its ⤢ choose the
  Specification column, the Example column, or Both. The choice is kept the next time the
  diagram is maximized; restored, the diagram stacks both columns.
- **F_max stops at the toggle ceiling**, 1000 × 0.45 / t_RF,max, where 0.45 is the shortest half period as a fraction of the period: 54.2 MHz on SWI3S, from its
  8.3 ns slowest edge. A leg whose margin scales with the UI and passes up to the ceiling reads the
  ceiling, and its tooltip names it; the launch hint reads "bound by t_RF" there.
- **Settings the timing model cannot evaluate show why.** A threshold at or beyond the transmitter's
  rail clears the margins, and the advisory line names the column and the threshold. Loading such
  values from a settings file, a workspace or Load Example raises an import warning. A settings file
  holding a clocked launch mode for a SoundWire Manager warns that the analog launch is used.
- **An edited Example Man_t_DD, Man_t_ZD or Man_t_DZ is kept** across an F_CLK change, Save/Open
  Workspace, Save/Open Timing Settings and Load Example. Under a clocked launch the value stays on
  the mode's grid, an F_CLK change keeps its UI fraction, and a restored value that is off the grid
  is moved to the nearest point and reported in the import warnings. Changing the launch mode
  re-derives the three rows.
- **Bus Grid > Show Toggles (the TX map) works on PHY3 (DLV) captures**: rows follow the recovered
  Row Sync Points, so the raster and the persistence summary light the columns that carry
  transitions, in the Safe-Lock region and the operational region.
- **Audio decodes each stretch of a channel at its own sample size.** When a port's sample size
  changes mid-capture (a SampleSize write or a reconfiguration), a 1-bit stretch is decoded as PDM
  and a wider one as two's complement, and all of them are scaled to the channel's widest width.
- **The PyInstaller bundle starts from `swi3s_studio/__main__.py`**, which is also `python3 -m
  swi3s_studio`.
- **A capture time that is not a sample index is refused or skipped.** A time more than 2**63
  samples from the capture start, or a .bin / v0 .sal header begin time that is nan or inf, raises
  an error naming the file. A transition time or analog sample time that is nan or inf is skipped
  with an import warning (.bin, v0 .sal, analog, digital CSV).
- **A Data Port numeric cell rejects a thousands separator** ('1,000'), and Save Settings / Export
  JSON / Compare do not abort on such a cell.
- **Save bus config, Export bus grid, WAV export, Save Example, Export commands (one Link and all
  Links), the per-channel `.bin` export and the raw capture CSV export keep the previous file when
  a write fails**, with no temporary file left beside it. A file name too long for the temporary
  file is saved in place rather than failing.
- **Save dialogs ask before replacing a file** that a name typed without an extension names once
  the format's extension is added (`grid` → an existing `grid.svg`): Export bus grid, Save
  workspace, Save bus config, Save Example and the other saves. The dialog itself asks only about
  the name as typed. A dot inside a name (`run 1.5`) is not taken for an extension.
- The Bus Grid image export and Save timing settings are written whole, so a failed write keeps
  the earlier file. Export bus grid refuses a PNG over 1 GiB and names its pixel size; SVG has no
  such limit. The Force value prompt names the 0x, 0o and 0b prefixes.
- **A legacy scalar `CDS_TailWidth_REG` or `CDS_DriveType` below its legal range (a negative value)
  is ignored and reported** by every config import (the decode's, the Analyzer's and the
  Visualizer's), which no longer refuse the file or apply the value: the CDS sources keep their
  defaults.
- **Register-map import bounds what it reports.** A register that repeats an earlier register's
  name carries no fields (the fields go to the first) and is reported, a name or access that is not
  text is reported, and the import warnings stay short however many distinct oddities a file has.
- **A digital CSV with a data line over the line limit is refused up front**, naming the file and
  line, before the line is held.
- **A workspace hub depth or scrambler-override key that is a fraction is left out and reported.**
- **The Handover Contention inequalities read in time order**: the releaser (a peripheral's
  detection of the closing edge, or under EndDriveEarly of the edge opening its UI, then the
  release), the handover UIs, then the acquirer; on P→P the two detections stay gathered ahead of
  the release. On Manager to Peripheral the bus is two `t_PD` terms, the clock's flight to the
  peripheral and its drive's flight back, around the peripheral's detection and turn-on.
- **The Bus Keeper inequalities read in time order**: the launch and its crossing of the keeper's
  threshold, the closing edge, on keeper_Per the spacing of the Peripheral's two detections, and the release, then
  the keeper's response. The response's note names the Manager's source: SWI3S Man_tKeeper_Response,
  or a SoundWire Manager's t_Keeper_Delay, with what each is measured between. A SoundWire anchor
  correction of zero is no term.
- **A SoundWire Manager's keeper counts from its own thresholds.** With a SoundWire Manager the
  releasing data must stay past V_TH_Keeper,max (65 %) or V_TL_Keeper,min (35 %) for
  t_Keeper_Delay before high-Z, as SoundWire 1.3 Figures 18 and 19 draw it: the keeper legs charge
  the crossing of that threshold, `X_K,rise,late` / `X_K,fall,late · t_RF`, at the Manager's supply
  and, for a releasing
  Peripheral, the ground shift, in place of a SWI3S Manager's V_IH,max / V_IL,min. An EndDriveEarly
  release charges that crossing's offset past V_OH.
- **A click on a Timing Calculator input row's name highlights its parameter**, as a click on one of
  its terms does, and a second click clears it. Clicking an EDE Delay row highlights the EDE release
  terms it sets, and an EDE release term highlights the EDE Delay row.
- **Clicking a term in the Timing Calculator draws it.** A term diagram opens on the right and draws
  the clicked term to scale in each column, at that inequality's worst corner: the clock and data
  edges it connects at the pin it is measured at, as their ramp model's curves, both grounds and the
  receiver's threshold from its own ground, and the term's length in ns; a flight mismatch as the
  clock's and the data's propagation and the difference between them. Every inequality: a release
  goes dotted at high-Z, a turn-on leaves dotted high-Z, an EDE Delay runs from its ramp's 80 %
  point, a keeper's response from the keeper's crossing, and the margin is green for a gap and red
  for an overlap or a short. The diagram's ⤢ and a double-click give it the whole page with the two
  columns side by side, and View ▸ Maximize Pane puts it back. Each column has a Corner line naming
  the rows off typical and each device's V_SEOS.
- **The Timing Calculator shows an equation row per column where the columns price different
  terms**, such as a release by t_DZ against one by an EDE Delay, so Man_t_EDE and Per_t_EDE are
  clickable on an EDE bus and open their diagram; columns with the same terms share one row, in the
  page and in the copied summary.
- **SoundWire 1.3 is offered at 1.2 V only.** A saved Timing setting that names the 1.8 V source
  warns on load and keeps the current selection.
- **A SoundWire 1.3 side carries its SWI3S equivalents.** Each Table 17 value is re-measured between
  the SWI3S anchors for the same event, on the side it is on, and the calculator evaluates it under
  the SWI3S anchor rules, moving each launch to the operating slews by SoundWire's own anchors (t_OV
  at 80 % of the data ramp, t_ZD_Data at low impedance; a `,anchor` term shows the move, and is zero
  at the slews each equivalent is derived at: the system size's t_Slew_Clock,max on the max side,
  5.0 ns small and 6.0 ns large; on the min side the clock at t_Slew_Clock's min, 2.0 ns, with the
  data at 5.0 ns on a Peripheral and 2.0 ns on a Manager). At 1.2 V, small system: a Peripheral's t_DD and t_ZD are 9.7–22.9
  ns, t_DZ 5.3, t_IS 0.0 and t_IH 4.0; a Manager's t_DD and t_ZD are 9.7–26.7 ns, t_DZ 9.1, t_IS
  −1.0 and t_IH 7.8, and its keeper responds in 2.5 ns. A SoundWire Peripheral's clock detection is
  no longer charged twice on the P→M legs, and its t_DZ rows start at 0 like a SWI3S side's. The
  t_IS boxes accept a negative value.
- **The worst-corner search takes the slews, τ, α and δ together on every bus.** The Manager's
  clock t_RF lane (its data lane following it), the Peripheral's data t_RF lane, the per-edge slew
  tolerance τ, the noise allowance α and the supply tolerance δ are searched together: τ, α and δ
  over every combination of their min, typ and max, and each slew row over its whole range. Each
  inequality shows the worst corner it can reach, also with the V_IH / V_IL windows edited low, with
  the Man DATA t_RF range edited apart from the Man CLK one, and with a large noise allowance. Where
  an edge stops at the end of its spec's slew range, the other edge's t_RF turns back, so a margin
  can be least inside the row's range. The search evaluates the row there, and the Corner line
  names the row's value (t_RF Man CLK at 5.70 ns). On the default rows no margin moves; with a Man
  CLK t_RF range of 1.0-6.0 ns and the Man DATA lane linked, M→P setup reads 0.04 ns less.

  Its term's note says it was raised, and the margin and F_max describe the same Manager.

  per-edge slew tolerance τ of 100 % or more (or below 0), a value that is not a finite number, and
  a clock rate, trace velocity or nominal supply of zero; a negative t_RF, bus length, t_PD,mis
  fraction, α or keeper response; such an input does not leave the previous
  margins on screen. Loading such a value from a settings file or a workspace is reported as an

  flushes a pending edit first, so a value set and read at once is the recomputed one.

  mode**, as it already did for TX-controlled and Async. For a port that is not sub-row-interval,

  commit takes effect; the symbol viewer, TX map, grid and bus rows follow it per region. An
  authored PHY3 config places the CDS after S1, its tail and its handover, as the Visualizer does,

### Other changes and fixes

  label finds no free spot, and a heading wider than the plot wraps within it, so no text overlaps

  platform, and the recovered Row Sync log holds each row's edge exactly. On Windows a rising edge
  near the top of the sample range decoded one extra row of UIs.

  Windows log) as `?` rather than stopping with a UnicodeEncodeError.
- A flow-control DRQ bit is read on its last UI, in both directions, so a wide DRQ bit, or one cut
  short by the row edge, is read where it ends. The bus grid places a source DRQ on the first UI of
  its bit.
- A decode cancelled from the UI is discarded as a whole: the session keeps its previous decode and
  inputs.
- A scrambled data-port channel that stays enabled across an SSCR keeps its scrambler state; only
  enabling the channel, or its ScramblerEn bit going 0 to 1, reseeds it.
- The flow-control port scrambler is decoded: FCP_ScramblerEn (0x0E bit 3) descrambles each DRQ bit
  with a per-port LFSR seeded when the port is enabled. A config CSV carries FCP_ScramblerEn at its
  reset value 1, and `make_demo_levels_flow_control(n, fcp_scrambled=True)` generates a capture with
  it set.
- A ScramblerEn (0x0B) or FCP_ScramblerEn (0x0E) bit going 0 to 1 seeds that scrambler fresh,
  whether it is set by an immediate write or by an SSCR, instead of resuming the state it had when
  cleared; a bit that stays 1 continues.

  starts there carries the new channel set, and one whose transport has already begun finishes on
  the set it began with.

  in-flight `run()` from another thread within 4096 UIs of reading, plus at most one detect window

  without reading the source. `request_stop()` takes effect within the same bound, also during the
  leading detect window, a re-detect window and a Link's inactive stretch. A `Decoder` runs once: a
  second `run()` raises, also when the first read no UI.

## Testing

- **What runs where, and when, is one strategy** (`docs/TESTING.md` §1.1). Every test is marked for
  what it protects (`core`, `gui`, `platform`, `perf`), and each stage has a scope: the dev loop,
  the commit gate, a guest scope and the release gate before a tag. The commit gate and the guest
  gate have time budgets, the dev loop a 2 minute target, and the release gate none. The gate prints
  each check's time and names a commit or guest stage that runs over its budget.
- **The gate runs the suite in parallel.** Each test file runs in a process of its own, one per CPU
  at a time, and the heaviest files are spread over several workers each (pytest-xdist). This is the
  suite's result and the teardown-crash check in one run. `tools/gate.py` takes a stage: the commit
  gate by default, `--guest` (the `gui` and `platform` tests, a `core` smoke set, perf, the leak
  scan and the screenshots) and `--release` (also the single-process run and the native core's
  coverage; `tools/test_report.py` is run separately by hand before a tag).
- **The dev loop runs only what a change touches**: `python3 tools/changed_tests.py --run`.
- **Every CI job has a time limit**, and the gate bounds each check's processes: a hung tool is
  killed with what it started and named as a failed check. The test jobs may run 150 minutes and
  the coverage job 240.
- **`tools/changed_tests.py` maps fixtures, golden files and `data/` files** to the test files that
  name them, a `data/` file also through the package module that reads it.
- **`tools/package_smoke.py` and `tools/mypy_gate.py` refuse an unknown option** with exit 2 before
  doing any work, and the package smoke test checks that the headless run wrote a bus model.
- **`--record-sync` refuses a last sync point that is no longer on the upstream branch.**
- **Durations are kept**: each suite run writes every file's and test's time to
  `build/test-durations/<platform>.txt` (`<platform>-guest.txt` for a guest run).
- **Coverage measures more**: branches as well as lines, `tools/` as well as the package, and the
  subprocesses a test starts. CI's floor is 82% of lines and branches, and CI's test and coverage
  jobs run one file per worker.
- **The native core's coverage is measured** in the release gate, from an instrumented build
  (`tools/native_coverage.py`, clang's `llvm-cov`), where those tools exist.
- **A test report before each tag** (`tools/test_report.py`): coverage per subsystem, the files with
  the most lines unrun, redundancy and fragility from per-test coverage, and the slowest files and
  tests.
- **`pytest-xdist`** is in `requirements-dev.txt`.
- **The native core's coverage report** also writes each source file annotated with its line and
  branch counts (`build/native-coverage/show/`).
- **`tools/native_coverage.py` names its report by its absolute path** where the report is on
  another drive than the checkout (Windows).
- **New coverage**: the config CSV warnings and hex/binary cells, the reported rate of a
  sub-row-interval port, the payload engine's source-shift and bit-dump diagnostics, a DSCR that
  enables a port, the Visualizer's clash rules, its Interface model, its bus-model JSON and its
  labels.
- **The timing cross-check runs everywhere.** The reference analysis's values are vendored as
  `tests/fixtures/timing_reference.json`, with the module and revision they came from;
  `tests/test_timing_vs_reference.py` reads them always. With the reference checkout present it also
  fails, naming each value that differs, when the fixture is stale, and the fixture is rewritten
  only by `PYTHONPATH=. python3 tests/test_timing_vs_reference.py --regenerate`.
