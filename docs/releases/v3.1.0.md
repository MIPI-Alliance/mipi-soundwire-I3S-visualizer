# SWI3S Studio v3.1.0

This release includes everything in 3.0.24, 3.0.23, 3.0.22 and 3.0.21, described in
`docs/releases/v3.0.24.md`, `docs/releases/v3.0.23.md`, `docs/releases/v3.0.22.md` and
`docs/releases/v3.0.21.md`. It adds the Commands table's ΔRows and ΔTime columns, a register
History window, Evenly Spaced audio, and a warning from every importer that lists what it did
not read as written. The Timing Calculator gains F_max on its hold, contention and keeper
legs, the proposed revision's Example values and a Timing Inequalities pane that maximizes,
and follows View ▸ Appearance. Tabbed panes show their tabs in the title row. EndDriveEarly is
not yet modelled on v1.1 r10; see below.

## Changes

- **"Offset" reads "Time Offset".** The Link label's menu item is now **Set Time Offset…**, its
  dialog **Set Link Time Offset**, the Open Capture dialog's field **Time Offset**, and the
  status bar says "time offset".
- **Playback Output Device and Playback Bit Depth are greyed until a capture is open**, like
  the rest of the Audio menu.
- **A register map with 32-bit registers and a separate field list imports.** Each register is
  split into the byte registers the bus addresses (little-endian: byte k of A is A + k), fields
  across bytes are sliced per byte and named by their own bits (`GAIN[15:8]`), and field
  descriptions and value labels are kept, in the normalized JSON too, so a workspace keeps
  them. A default is read as its `format` attribute says (hex, bin or dec); without one, `0x`
  is hex, `0b` binary, digits of 0, 1 and X alone binary, and other digits decimal. A default
  of 0s and 1s with no prefix or format is read as binary and reported, as are an unknown
  format and a default that is not a number. Digits not written are zeros, so `0x1` on a 5-bit
  field resets to 1. `X` digits are unknown, and so are the digits above a leading `X`.
  Registers outside the device-defined address space (0x10000000–0x3FFFFFFF and
  0x90000000–0xBFFFFFFF) are skipped and counted; the SWI3S spec addresses among them are
  decoded by the spec map.
- **An imported register's width rounds up to 8, 16, 32 or 64 bits.** A 32-bit register whose
  default is written short (`0x0`, `0x050041`), or whose top field ends below bit 24, imports
  as four bytes with no false "not aligned" warning.
- **Register-map importers are named for the shape they read**: the rootless
  `<register>`/`<bit>` importer is `BitListXmlImporter`, format `bit-list-xml`.
- **The Timing Calculator follows View ▸ Appearance** without a restart.
- **The Commands table keeps its order** when Commands: All Links is turned off, and a saved
  workspace no longer records a sort that was never applied. A workspace saved by an earlier
  version may reopen sorted by Row descending; click the Row header to put it back.
- **macOS menus show ⌘ for every shortcut.**
- **Statistics ▸ Regions reports each region's clock as the average** edge spacing, idle gaps
  excluded, agreeing with the status bar.
- **Commands: ΔRows and ΔTime columns**, each beside the column it counts (Row, ΔRows, Time,
  ΔTime), hidden until shown from the header's right-click menu.
  Each counts from the row above as the table shows it, so a filter to one command kind reads
  that kind's spacing. In All Links, ΔRows is blank between two Links' rows and ΔTime is on
  the shared timeline.
- **Hidden Commands columns are kept by name**, so a hidden column stays hidden when All Links
  adds its Link column. A workspace records its columns, so a column added later keeps its
  default.
- **Audio: Evenly Spaced.** Right-click a channel whose samples arrive unevenly, a Payload
  Interval Skipping stream such as 44.1 kHz over 48 kHz rows, to draw it at its average rate.
  The waveform is no longer lumpy and the spectrogram is the clean spectrum of the samples.
  As Transported goes back, and its spectrogram is of the signal as transported (each sample
  held until the next), so the skip pattern's spurs show. The Link keeps the setting through
  a re-decode, and the workspace saves it.
- **Spectrograms use a Blackman-Harris window** and remove each frame's window-weighted
  mean: a full-scale tone's leakage is under −90 dB beyond 5 bins and under −100 dB beyond
  10, columns no longer stripe from one to the next, and the bottom bins no longer carry a DC
  term.
- **Registers: History….** Right-click a register for every write and read of it, with the time,
  bus row, value and whether it took, including attempts that failed (CRC errors, WRITE_FAILED
  or READ_FAILED, error tokens, no response). Failed attempts are tinted and can be shown
  alone. Double-click an entry to jump to it. A deferred read whose ReadData failed or got no
  answer is listed under the read's address. A (CURR) row lists its (NEXT) writes and the
  Commits that promote them, with the value each Commit promotes.
- **Timing Calculator: the launch hint on an EDE bus** says the selector applies to the EDE
  column only; the Specification column keeps its tabulated analog delays.
- **The bundled example register map** (`example_amp.json`) has invented register names,
  addresses and resets. A workspace that bound it shows the new names.
- **Commands: a column shown from the header menu after a Link switch, an All Links toggle or
  a workspace reopen gets its width**; ΔRows and ΔTime no longer come back 0 px wide.
- **Commands: column widths are saved by column name.** A workspace saved before the delta
  columns existed keeps its columns fitted rather than shifting its widths onto the wrong
  columns.
- **Commands: ΔRows and ΔTime cannot be sorted.** A click on either header leaves the sort as
  it was, and a workspace does not save a sort on them.
- **Commands: reopening a workspace saved in capture order puts the table back in capture
  order**, clearing a sort made before the reopen.
- **Commands: on an error row, the ΔRows and ΔTime cells explain the error** in their tooltip,
  as every other cell of the row does.
- **Registers ▸ History…: a double-click lands on the command's Row Sync Point**, as selecting
  it in Commands does. It lands on the History window's own Link even after another Link is
  removed. The window closes when its Link is removed or a new capture is opened, and follows
  a theme switch.
- **Registers: an open History window follows a re-decode of its Link** (Force Column Count, a
  what-if register edit, a scrambler or hub-depth change, an SSP step): it lists the accesses
  of the new decode, and a double-click lands on one of them.
- **Registers: a Commit promotes only the devices its Device Mask selects**, in the Registers
  pane, the Bus Grid and audio decode as in Register History; a zero mask selects none. A
  device the Commit leaves out no longer shows a _CURR value in the Registers pane that
  History cannot account for.
- **Registers ▸ History… ignores a write that selects more than one device, as the Registers
  pane does.** A WriteA32 must select exactly one device; History lists a multicast one as
  not applied, with its device-mask error, and a later Commit no longer shows it promoted
  into (CURR).
- **Registers ▸ History…: a write to a (CURR) register sets (NEXT) too, as the Registers pane
  does.** A Commit after a direct (CURR) write promotes the written value, and a (NEXT) row's
  History lists the (CURR) writes as "Write (CURR)".
- **Registers ▸ History… starts again at a bus reset.** After a later Cold Start's Bus Reset, a
  (CURR) row's Commits use the reset commit-group membership and the values staged since the
  reset, as the Registers pane does.
- **A Link added while a workspace opens keeps its own state.** Each saved Link's name, time
  offset, stream settings, Commands view and cursors are applied to the capture they were
  saved for, even when another Link is added or one is removed while the workspace loads.
  Cursors placed on any Link while the workspace loads are not kept.
- **Help ▸ Timeline Marks Legend… describes the playhead without naming a colour**; its swatch shows the
  colour in each appearance.
- **Timing Calculator: P→P setup margins follow the Peripheral DATA lane.** PP_setup and
  PP_setup_ho took their margin from the Manager DATA slew while their equations showed the
  Peripheral DATA slew, so the two disagreed whenever the two lanes differed, and Auto-worst
  never moved t_RF Per DATA for these legs. The margin now equals the equation beside it on
  every leg, and the substitution row's numbers, as printed, add up to it: a term whose own
  value is negative keeps its sign (`− (−2.00)`), as an EndDriveEarly release can.
- **Timing Calculator: a Peripheral's EndDriveEarly release is 1.67 ns earlier.** It is the
  pure Per_t_DD plus the full rail-to-rail swing plus the hold interval; the tabulated
  Per_t_DD already contains the first 20 % of the ramp, which was being counted twice. P→M
  and P→P contention with an EDE peripheral releasing improve by 1.67 ns: in the EDE column
  P→M contention reads +3.49 ns (was +1.82) and P→P contention +0.59 ns (was −1.08).
  PP_hold_ho still fails at zero handover UIs (−7.67 ns), so a P→P handover still needs its
  UI. The Per_t_DZ,EDE term's note lists the four parts.
- **Timing Calculator: anchor-conversion notes show the slew the conversion uses**, which is
  the spec's reference t_RF (5.00 ns SWI3S, 5.40 ns SoundWire 1.8 V) and not the lane's
  operating t_RF, with the coefficients as numbers so the note recomputes to the pure value.
  SoundWire notes include the clock-side re-anchor.
- **Timing Calculator: M→P and P→M contention no longer show a 0.00·0.00 clock-crossing
  term** for the Manager end, which has no crossing of its own. Margins are unchanged.
- **Timing: a clocked Manager launch no longer understates the setup F_max.** A 2× or 4×
  launch places Man_t_DD and Man_t_ZD at a fraction of the UI, so the MP setup legs' Example
  F_max now includes it: 2× at 12.288 MHz reads 24.6 MHz, matching the launch hint, where it
  read 16.4 MHz.
- **Timing: contention F_max includes an EndDriveEarly release.** An EDE release is one UI
  earlier than a conventional one, so a contention leg on it changes with the rate even with
  no handover UI. A zero-UI deficit now reports the rate that closes it instead of 0.0, and a
  one-UI allocation no longer reports about twice the true limit. Margins are unchanged.
- **Timing Calculator: under a 2× or 4× launch, the MP_setup and MP_hold Man_t_DD notes give
  the clock-grid snap and then the snapped value**, which is the value the margin uses.
- **A flow-controlled port's waveform is one continuous trace.** A TX, RX or ASYNC port that
  declines several transport opportunities in a row no longer reads as a dropout, so the
  waveform is not cut into thousands of pieces. A real dropout on such a port is still a
  gap: each run either side of it is drawn evenly between its own first and last samples,
  and the rate shown, played and used for the high-pass is the runs' rate.
- **Audio: a port that groups several samples onto one row (SampleGrouping) is no longer
  drawn as separate bars.** The step to the next row was read as a transport gap at every
  group. Evenly Spaced is now offered for such ports, and the spectrogram's evenly spaced
  placement uses the true average step.
- **A digital CSV or `.bin` opens at its own sample rate.** The rate is read from the grid
  the timestamps sit on, not the finest spacing, so a capture exported at 500 MHz (one row
  per transition) reopens at 500 MHz rather than 50 MHz, with every edge where it was. A
  digital CSV whose first row is long before the bus comes up can still be read at the
  wrong rate.
- **Opening a large analog capture, VCD, digital CSV or `.bin` pair is refused before it
  exhausts memory.** A scope CSV, a `.wfm` pair and a `.bin` pair are checked against the
  memory budget before their samples are read (a `.bin` file by its whole size when its
  header counts fewer transitions than it holds), a VCD stops once its edges pass the budget, and each now takes far less
  memory to load (a 1M-row scope CSV about a tenth, a `.wfm` pair about half). The Open
  Capture dialog's memory figure is the one each loader checks.
- **A `.sal` window the Open Capture dialog says fits opens** when its two busiest channels
  are the Link's. The dialog and the loader price a window the same way for those channels,
  and a refusal reports what the window needs and asks for a shorter one. A window of a capture stored as very large blocks no longer decodes them
  whole.
- **A `.sal` window over the busy part of a mostly idle capture is priced by what it holds.**
  The window is priced by the blocks it overlaps rather than by its share of the capture's
  length, so a window over the active end of a capture started long before the bus came up
  is no longer admitted at a fraction of its memory.
- **A small window of a large `.sal` opens faster**: the capture is inflated about once, not
  three to four times.
- **A corrupt `.sal` is refused** rather than opening a window with out-of-order edges, when
  the damage is in the blocks the window reads.
- **Picking a large digital CSV in Open Capture is quicker**: telling digital from analog
  reads a bounded sample of the file.
- **A CSV whose time column is not named TIME is refused after its first rows** in Open
  Capture, rather than being read whole before the refusal.
- **A digital CSV whose header row ends in a comma shows its edge counts and sample rate** in
  Open Capture, with no extra unnamed channel, matching what loads.
- **A PHY3 (DLV) capture's load shows its progress.** The progress bar fills as the decode
  runs, as it does for PHY1 and PHY2.
- **A config CSV's SampleSize_REG reads at its 5-bit register width.** A value above 31, or
  below 0, decodes as its low five bits, the width the bus grid and register map show. The
  audio store holds every bit of each sample.
- **A long capture decodes without an up-front audio allocation sized to its length.** The
  decoder reserves at most 64 MiB for audio before decoding, and nothing when audio decoding
  is off.
- **A single-ranked data-port write no longer breaks the samples in progress.** After an
  immediate WriteA32 to SampleSizeGrouping, PortControl, FlowMode or SkippingNumerator, the
  sample being assembled on each channel finishes with its own start time and value, sample
  numbering carries on rather than restarting at 0, the descrambler is not reseeded, and the
  flow-control handshake check keeps its DRQ history.
- **A config CSV that does not load is reported, not drawn.** `-c config.csv -o model.json`
  exits 1 with the CSV loader's message (for example a row with the wrong number of cells)
  and writes no model, rather than building it from the part of the file that loaded; the Bus
  Visualizer shows the same message as an Engine issue.
- **Python API:** `swi3score.TransitionSampleSource` accepts edge arrays of any integer dtype
  that converts safely to uint64, strided views and lists, converting them once; a
  C-contiguous uint64 array is still used without a copy. `forced_column_count` outside 2–32
  auto-detects the column count. `Decoder.progress` is clamped to [0, 1], and
  `Decoder.audio_capacity` reports the audio records allocated.
- **A `.wfm` pair the Open Capture dialog says fits opens.** The pair is checked against the
  memory budget once, before either file is read.
- **Timing Calculator: P→P data crossings follow the Peripheral's ramp shape.** Peripheral A
  drives the data peripheral B samples, so B's data crossing on Per_t_RF,DATA takes the
  Peripheral's shape, and the clock lane keeps the Manager's. With a linear Manager and an
  exponential Peripheral, P→P hold's data crossing is 0.23·t_RF where it read 0.45·t_RF,
  about 1.1 ns less hold margin at 5 ns (1.85 ns at 8.3 ns); with the shapes the other way
  round, P→P setup is charged 1.44·t_RF where it read 1.31·t_RF. With equal shapes nothing
  changes.
- **Timing Calculator: F_max on hold, contention and keeper legs.** A leg whose margin scales
  with the UI shows the rate where it closes, at the clocked placement it starts from: a
  clocked Manager t_DD or t_ZD on M→P hold, the
  handover UIs on the handover-hold legs, the closing UI on the keeper legs, and the
  contention legs. The binding rate is the lowest over all legs that bound the bus: under a
  4× launch M→P hold closes at about 16.95 MHz on the hint's own inputs, and a zero-UI
  peripheral EDE release can be bound by P→M contention. On the default page the keeper legs
  read 12.92 MHz (Manager releasing) and 12.80 MHz (Peripheral releasing) in the
  Specification column. — means no rate bounds the leg, FAIL that none closes it. Margins
  are unchanged. Above the rate where a clocked fraction falls below its row's minimum, the
  page moves Man_t_DD up a grid point and the F_max shown does not follow it.
- **Timing Calculator: a releasing peripheral's clock detection on P→M and P→P contention
  reads X_MP,late.** It carries the coefficient of M→P hold's late clock crossing; X_PM,late
  is P→M setup's clock addend, which differs once the lanes' t_RF or the devices' ramp shapes
  differ. Margins are unchanged.
- **Timing Calculator: SWI3S PHY2 (EDE proposed) results carry the PROPOSED note** in their
  caveats, like the proposed revision: both are unratified values.
- **Damaged or partly written captures give a clear error.** A `.bin` or `.sal` channel that
  lost its tail is reported as truncated, with the file and the counts, and a damaged
  transition count no longer reads as needing many GB. A scope CSV whose last row was cut
  mid-number opens without that row. Any other unreadable row is named by number and text.
- **A windowed `.sal` open prices a damaged channel whole.** A channel whose data does not
  walk as a block chain is read whole whatever the window, so the memory check counts it
  whole and the refusal names that channel, within milliseconds.
- **A config CSV that starts partway into a row finds the DRQ bits of RX_CONTROLLED and ASYNC
  ports at their configured column.** Each sample's drq_sample points at the UI its DRQ was
  on, and the flow-control statistics count only the handshake failures on the wire.
- **A SampleSize change made by an immediate (single-ranked) write while a sample is in
  flight keeps that sample intact.** It finishes at the width it started with, with the
  right value, start and bit-width label, and the samples after it use the new width.
- **A config CSV whose DeviceNumber_REG is outside 0-11 gives one view** when the row is
  present. That port names no
  device on the bus and is left out of the audio decode, the grid and the register map
  alike, and a session load no longer fails with a cast error.
- **Skip This Link opens the workspace's other Links.** Skipping the first Link's missing
  capture no longer leaves the window empty with an Open failed error, and skipping every
  Link opens nothing, with no error.
- **Locate Sub-Capture places its cursors on the capture it searched.** If another capture replaced it
  while the search ran, the results are discarded and the status bar says so.
- **Bus Grid persistence keeps its own Link's CDS column** when another Link is made active
  while the persistence scan runs in the background. A scan that finishes after the grid
  shows another Link's bring-up message can still paint over it.
- **The Timeline follows Clear All Filters.** It no longer keeps showing the previous
  filter's command marks until the next filter change.
- **A Visualizer CSV the app saved loads with no missing-field warnings.** The CDS guard and
  tail registers are read from the file's per-source rows, so they are no longer logged as
  missing "using default".
- **Audio ▸ Export…, Visible range** writes the same stretch of time for every selected
  stream, each at its own rate.
- **CDS and PHY Control registers are dual-ranked** in the register model behind the Registers
  pane, the Bus Grid and audio decode: a _NEXT write takes effect at a confirmed Commit
  (Commit Group 0). A PHY Control _CURR write takes effect at once; a CDS _CURR alias is
  read-only (Dual-CURR-is-RO), so a write to it changes nothing.
- The native decode core changed (`score_abi` 16), so it must be rebuilt
  (`bash native/build_local.sh`, or `run.sh`/`run.ps1`, which rebuild a stale core). A core
  built before this release is refused rather than decoding without the Device Mask and the
  dual-ranked CDS and PHY Control registers.
- **A commands-only decode (`decode_audio=False`) follows NumColumns commits**, so its commands
  and column regions match a full decode.
- **Import warnings.** Any import that skips, clamps, masks, defaults, truncates,
  reinterprets or ignores part of a file says so in an **Import warnings** window, one per
  import, titled with the file and listing each warning, with the count in the status bar.
  The window is not modal. A file that cannot be read is still an error.
- **Captures report what they did not read as written**: in a `.vcd`, x/z values, times
  going backwards, a signal with no 0/1 value and a `$timescale` that is not a whole number
  of hertz; in a digital CSV, short rows, unreadable times and levels, rows out of time
  order and an assumed rate; the snap of a DLV capture's rate to a standard one; in an analog
  CSV or `.wfm` pair, a dropped last row, short or long rows, samples out of time order or
  not numbers, thresholds that could not be detected and a TIME column disagreeing with the
  preamble; in a `.bin` pair, bytes past the counted transitions, times off the sample
  grid, files starting at different times and transitions merged onto one sample; in a
  `.sal`, channel entries with no file and a window past the capture's end.
- **A `.bin` pair whose transition times step back is read in time order.**
- **A Visualizer config CSV reports what it did not read as written**, when it is opened,
  imposed on a capture or a region, or compared: a port whose DeviceNumber_REG names no
  device (it is disabled), values that do not fit their register field (SampleSize masked
  to 5 bits, NumColumns outside 1..31), cells that are not numbers or booleans, values past
  the last column, unrecognised or missing fields, and a legacy or v2.0 file whose upgrade
  drops a field or fails.
- **A register map reports what it did not read as written**, on import and when a stored
  map is read back: registers with no usable address, duplicate addresses, fields with an
  unreadable bits spec, unreadable resets and value labels, and attributes the model does
  not keep. The warnings of a map bound in **Devices ▸ Register Maps…** are shown
  when the dialog is accepted.
- **A reopened workspace lists what it could not restore** in one window titled with the
  workspace file: settings this version does not read, values of the wrong type, register
  and scrambler overrides that do not read, a saved pane Link, mode or sort column that no
  longer applies, and a workspace saved in a newer format.
- **Timing settings and Load Example report** unknown keys, choices not offered and values
  pulled back into range.
- **The bundled Visualizer examples are in the current CSV format**, so they open without
  import warnings; each builds the same bus model as before.
- **The spec-figure examples are named for what they show, not a figure number**
  (`spec_figures/PCM_Stream.csv`), since figure numbers move between spec drafts.
- **File ▸ Open Demo Capture offers PHY1, PHY2, PHY2 (Flow Control) and PHY3 (DLV), each with
  a bundled workspace.** PHY2 opens two Links: the PHY2 demo as Link 1 and the flow-control
  demo as Link 2, delayed on the shared timeline. The workspaces (`data/demos/*.swi3s`) name
  the data ports (`AMP1`, `AMP2`, `MIC1` / `MIC2` or `MIC`; on the flow-control demo `No Flow Control`,
  `TX Synchronous`, `RX Synchronous`, `Asynchronous`) and config regions, and set the Audio
  channels and zoom, the Commands filters, the Capture view, the Registers blocks and filters,
  and the dock layout.
- **Commands: Time (µs), PhaseID, Opcode, Address, Register, Data and Response are shown by
  default**, each at a fixed default width; Row, ΔRows, ΔTime (µs), Devices, Packet Length,
  Group Mask and CRC are hidden until shown from the header's right-click menu. A workspace keeps its own column
  choices, and a column it does not record takes the default.
- **Registers: column widths are saved in the workspace** by column name and restored on
  open; a workspace without them uses the default widths.
- **Audio: the channel list is as wide as its longest entry**, plus its checkbox and margin,
  and still resizes with the splitter. A workspace's saved list width applies.
- **Bookmarks are Cursors, and the main cursor is the playhead.** The **Cursors** menu has
  *Toggle Cursor at Playhead* (⌘B), *Next Cursor* (⌘]), *Previous Cursor* (⌘[), *Clear
  Cursors* and *Align Links on Cursor Pair…*; the pane is **View ▸ Cursors**; Locate
  Sub-Capture's `Sub i/N` marks are cursors; Decode ▸ Manual SSP Move has *Set SSP at Playhead
  Row*; Help ▸ Keyboard Shortcuts lists *Playhead navigation*; the colour group is *Cursor
  pairs*; and the Timeline legend names the *Playhead* and *Cursor*. Shortcuts are unchanged,
  and a workspace from an earlier version opens with its cursors.
- **Hub Depths… is in the Devices menu**, which holds Device Names…, Register Maps… and Hub
  Depths…. Audio ▸ Export… writes WAV, and the per-port scrambler overrides are Decode ▸
  Dataport Scramblers….
- **Registers pane default column widths:** Register 258, Addr 63, Value 52, Fields 407 px.
- **Cold Reset values in the Registers pane are teal**, clear of the grey of a filtered key.
- **Register names in the Registers pane are drawn in the regular weight**; the colour shows
  the provenance.
- **Link names beside the timeline follow the theme**, so they are not black on the dark
  palette.
- **The Bus Visualizer's CDS Settings "Open…" button follows a theme switch**; it kept the
  theme the window started in.
- **Audio: zoomed in to the samples, a click puts the playhead on the nearest sample.**
- **Tabbed panes show their tabs in the title row.** Registers / Statistics / Cursors and Bus
  Grid / Capture / CDS / Audio / Samples / Timing each draw the group's tabs where the pane's
  title was, between the close and maximize buttons; there is no tab row below the panes, so
  the Commands and Registers horizontal scroll bars line up. A pane alone in its area shows
  its title.
- **Spec figures and tables are cited by caption**, not number, in code, tests and docs.
- **Windows: the Timing Calculator's input boxes show their values.** Under the app's
  stylesheet a buttonless spin box on Windows laid its edit field out 1 px wide; every input
  and the Clock Frequency Target read empty.
- **Windows: the Bus Visualizer's buttons fit their labels.** They take the width of their
  widest label where the platform font needs more than 180 px ("Open…" more than 64 px).
- **Bus grid text is centred vertically** on its capitals, in the Visualizer and the Analyzer.
- **Timing Calculator Example values (the proposed revision).** PHY2 adds Man_tDZ and Per_tDZ
  0–9 ns. PHY1: Per_tDD 14–42 ns, Per_tZD 17–42 ns, Man_tZD 22–56 ns, Man_tDZ and Per_tDZ
  0–9 ns, with Man_tDD 9–23 ns and Per_tIH 0–1.5 ns as on PHY2; a PHY1 bus opens on 6.6 MHz,
  its mandatory maximum. A 2× or 4× clocked Manager launch still places Man_tDD, Man_tZD and
  Man_tDZ on 0.5 or 0.25 UI.
- **EndDriveEarly is not yet modelled on v1.1 r10.** The calculator's EDE ceiling (0.60·UI
  + 10 ns from the start of the last driven UI) is its own working bound: the "PHY2 Output
  Timing: Effect of EndDriveEarly" table states different limits, references them to clock
  edges, and leaves the Manager's values TBD. The timing note calls it "the calculator's
  EndDriveEarly ceiling". Reworking the EDE legs to the table follows this release.
- **Timing Calculator layout.** The results are the **Timing Inequalities**, with a ⤢ (and a
  double-click on the title, or View ▸ Maximize Pane, ⌘⇧M) that hides the top bar, giving
  them and the parameter sections below them the whole page. Each
  parameter section's title is inside its box, so the sections are shorter. The ramp-model
  pickers are in the top bar, which does not scroll; the per-edge slew is in Rise/Fall Times;
  V_SEOS tolerance and V_noise join bus length and length mismatch in **System Properties**,
  which replaces Bus Properties and the Noise / Supply section.
- **The release gate renders every mode in light and dark** (`tools/screenshots.py`, the
  `screenshots` check) on the platform's own style, and fails on a pane in the wrong theme,
  text under 3:1 contrast or not drawn, a button, label or entry narrower than its text, and
  an entry or button that a live theme switch leaves looking unlike a window started in the
  new theme.
  Its contact sheet is the gate's visual review on each platform.
- **`requirements-dev.txt`** lists what testing needs (the runtime set, pytest, pytest-cov,
  ruff, and mypy at the baseline's version); CI installs it. `tools/setup_dev.sh` and
  `tools/setup_dev.ps1` install it and build the decode core into the launcher's venv.

## Publishing

- **CONTRIBUTING.md** says how to report a problem usefully and how to submit a pull request;
  the README's Contributing section leads with "use it and open issues", and a new Releases
  section names the supported versions. GOVERNANCE.md: a release that adds user-visible
  functionality is a minor release and a sub-minor release carries fixes only; security-only
  and pre-release tag forms; how to cite a release.
- **Versions are set only in the release commit.** The notes of the release in development are
  `docs/releases/next.md`; the version sites keep the last release's number until the release
  commit renames the notes and sets the new one. Work lands on `main` from short-lived
  `feature/`, `fix/` and `sprint/` branches, and a minor release creates its `vX.Y` branch.
  CI runs on pushes to `main`, `vX.Y` and those work branches.
- **A release tag is never moved or deleted**; the release checklist no longer describes
  rewriting an annotation.
- **The release commit needs no new guest run** when the guests gated its parent and it
  changes only the version sites, the examples' `AppVersion`, the notes file and the README's
  Releases section.
- **`tools/publish_tree.py` keeps what was merged upstream** (check 3b): it refuses to build
  while the upstream branch has commits the release tree has not taken in, or when the tree
  undoes a commit contributed upstream, in whole or in part: a file it added or changed is
  absent, or a sentence it replaced is back. Re-wrapping and line ends do not count, and a
  later edit of the contributed text passes. The record of what was taken in is
  `tools/publish_sync.txt`, published with the tree, and `--record-sync` appends to it only
  once the contributed changes are in the working tree. A release tree carrying `docs/releases/next.md`
  is refused; a `--preview` describes itself from it.
- **Deferred review findings are tracked as `tech-debt` issues.**
- **A publish lists every new name for approval.** `tools/name_review.py` lists each word the
  assembled tree has that the published tree does not, split out of identifiers and with no
  dictionary filter, and `tools/publish_tree.py`'s check 5b fails until it is re-run with the
  digest that approves exactly that list.
- **The name review reads more of the tree**: file paths, UTF-16 files and the printable text
  of binary files; a token mixing letters and digits is kept whole, so a part number is
  listed as itself; and a file over 4 MB is listed by name for a person to check, as part of
  the approved list. Run standalone, `tools/name_review.py` accepts the `--approve-names=`
  flag it prints.
- **`tools/publish_tree.py` fails its leak check when no site-specific patterns ran**
  (`$SWI3S_LEAK_PATTERNS` unset or empty), and always prints the scan's header.
- **The leak scan covers untracked files** that .gitignore does not exclude, and Windows home
  paths written with doubled backslashes (as in JSON) and Linux `/home/<name>` paths.
- **The CI lint job compares the mypy ratchet**: mypy is pinned to the baseline's version and
  reads no installed packages (`--no-site-packages`), so the count matches the local gate; a
  result that cannot be compared fails the job.
- **The gate asserts which native core it imported**: the one just built, not a stale
  `swi3score*.pyd` in the checkout root.
- **The leak scan reads a text file with a stray NUL as text**, and catches macOS volume,
  iCloud Drive and container paths and the absolute path of the tree it scans. An exported
  tree is walked whole except what its own .gitignore excludes. A pattern file holding no
  patterns is NOT RUN in the gate summary.
- **`tools/publish_tree.py` tests the published tree's own native core**: it compiles
  swi3score from that tree's native/ before running the suite, checks every file type for
  references to the internal tier, and fails its leak check when the scan read fewer files
  than the tree holds.
- **The name review lists more**: -er, -ers, -al and -ly derivations of published words and
  hex-shaped part numbers are listed, and approving a list approves the exact bytes of each
  file too large to read.
- **The mypy ratchet refuses a run that stopped early**: a blocking error is "mypy could not
  run", not a pass.
- **The mypy ratchet compares each platform with its own counts**: the baseline records
  per-platform counts (`per_platform`), so a rise on one platform fails even where another
  platform counts more.
- **`tools/leak_scan.py --tree=<dir>`** scans a directory that is not a checkout with the
  scanner's own patterns, and a symlink to a directory is scanned by its target path.
  `tools/publish_tree.py`'s check 5 runs this checkout's scanner on the assembled tree.
- **`tools/publish_tree.py` with no sha builds from HEAD and says so**, warning when tracked
  files have uncommitted changes, and its check 2 resolves relative links and symlinks into
  the internal tier.
- **The name review reads accented and non-Latin names whole** (NFC-normalised Unicode
  letters; a run of CJK or kana is one word), and reads a symlink as its target path.
- **`frame_model.json` at the checkout root is ignored by git**, like `bus_config.csv` and
  `init.csv`: no .gitignore pattern has a comment after it on the same line, which git would
  read as part of the pattern.
